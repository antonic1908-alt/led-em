# 02. ШІ-інструменти і система вайбкодингу для мікроконтролерів

> Стан на листопад 2026. Рейтинги ШІ змінюються щомісяця. Оглядові статті суперечать одна одній у цифрах бенчмарків і цінах, а частина з них є партнерським контентом. Перед покупкою перевіряйте ціни на сайтах виробників.

## Чим embedded відрізняється від «звичайного» вайбкодингу
- Код не можна просто запустити на ПК: потрібні **збірка → прошивка → реальне залізо або симулятор**.
- ШІ **не бачить плату**. Він не знає, що ви підключили, тому залізо треба описати текстом (`CLAUDE.md`).
- Головна помилка ШІ в embedded — **вигадані піни, адреси та регістри**, а також плутанина між версіями бібліотек (наприклад, API LEDC в Arduino-ESP32 2.x і 3.x відрізняється).
- Помилка в коді може не лише «впасти», а й спалити компонент (5V на GPIO 3.3V, MOSFET без резистора). Схему завжди перевіряє людина.

## Рейтинг інструментів для нашої задачі
Критерії: чи вміє інструмент сам запускати збірку (`pio run`) і читати помилки, якість C/C++ та Arduino/HAL-коду, робота з PDF-datasheet, ціна і поріг входу.

**Рекомендація для навчання:**
- **VS Code + PlatformIO + Claude Code** як основний агент.
- Чат (Claude або ChatGPT) у браузері для теорії та datasheet-ів.
- Якщо бюджет нульовий: GitHub Copilot Free або Gemini CLI + Wokwi в браузері.

Локальні моделі (Ollama тощо) для початківця не рекомендуються: вони значно частіше вигадують API.

## Як побудувати систему вайбкодингу: «замкнений цикл»

```
   ┌──────────── ви формулюєте задачу ────────────┐
   ▼                                               │
 ШІ-агент пише код ──► pio run (збірка) ──помилки──┘
                          │ ок
                          ▼
                  Wokwi (симуляція) ──не працює──► лог/опис агенту
                          │ ок
                          ▼
              прошивка на плату + Serial Monitor
                          │
                          ▼
             лог [модуль] ... ──► агенту на аналіз
```

### Що налаштувати один раз
1. **`CLAUDE.md` у корені проєкту** (є в цьому репозиторії). Агент читає його автоматично. У ньому: перелік заліза, таблиця пінів, адреси I2C, обмеження (3.3V логіка, strapping-піни) і команди збірки.
2. **Datasheet-и в `docs/datasheets/`** (PDF з сайтів виробників). Кажіть агенту: «спершу прочитай datasheet BH1750».
3. **PlatformIO CLI.** Агент сам запускає `pio run` і бачить помилки компілятора. Це головна перевага агентів над чатом.
4. **Wokwi** (`diagram.json` + `wokwi.toml` у `firmware/`). Перевіряйте логіку без заліза.
   - Для автоматичних тестів є Wokwi CLI: `wokwi-cli --timeout 10000 --expect-text "[ctrl] ready"`. Потрібен токен Wokwi; умови ліцензії перевірте на wokwi.com/pricing.
5. **Git.** Комітьте після кожного кроку, що працює. Якщо агент «наламав», повертайтеся назад: `git restore .`.
6. **Однаковий формат логів:** `[light] lux=12.5`, `[ctrl] state=ON`. Такі логи легко копіювати агенту.

### Шаблони запитів
- **Новий модуль:** «Додай модуль X. Використовуй тільки піни з `config.h`. Без `delay()`. Після змін запусти `pio run -e esp32c3` і виправ помилки. Поясни зміни як для C#-розробника.»
- **Налагодження:** «Ось лог з Serial Monitor: … Ось що я бачу на платі: … Що не так? Спершу запропонуй гіпотези, не змінюй код.»
- **Навчання:** «Розбери файл `Controller.cpp` рядок за рядком. Порівняй зі state machine в Unity Animator. Дай 5 контрольних питань.»
- **Перевірка схеми:** «Ось моє підключення: … Перевір за datasheet AO3400 і HC-SR501, чи нічого не згорить.»

### Правила безпеки
- Ніколи не довіряйте ШІ в питаннях **напруги та струму**: перевіряйте мультиметром і за datasheet.
- Не дозволяйте агенту змінювати піни без вашого підтвердження.
- Великі зміни робіть через «план → підтвердження → код» (у Claude Code є режим планування).
