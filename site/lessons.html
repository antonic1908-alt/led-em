Перед уроками: «Arduino» чи «C++»?

Кожен урок починається з рядка #include <Arduino.h>. Звідси часте питання: ми пишемо на Arduino чи на C++? Це не вибір «або-або». Весь код уроків і проєкту написаний на C++, а Arduino — це бібліотека (фреймворк), написана на C++, якою ми користуємось.

Аналогія з UnityВи ж не кажете «я пишу на Unity, а не на C#»: ви пишете на C#, використовуючи Unity. Тут так само: пишемо на C++, використовуючи Arduino.

Що робить #include <Arduino.h>

#include буквально вставляє вміст файлу Arduino.h у ваш файл перед компіляцією. Після цього компілятор знає:

  • функції роботи з пінами: pinMode, digitalWrite, digitalRead, analogRead;
  • час: millis(), micros(), delay();
  • об'єкт Serial для логів;
  • типи uint8_t, uint32_t і константи HIGH, LOW, INPUT_PULLUP.

Без цього рядка pinMode(...) дасть помилку компіляції «not declared» — як у C# без потрібного using.

Де ж тоді main()?

У звичайній програмі на C++ усе починається з main(). Вона є і тут, просто захована всередині фреймворку. Спрощено:

int main() {
  init();          // налаштувати чип: тактування, таймери, USB
  setup();         // ВАША функція — один раз
  for (;;) {       // нескінченний цикл
    loop();        // ВАША функція — знову і знову
  }
}

Як у Unity: ігровий цикл належить рушію, а ви пишете лише Start і Update. На ESP32 замість main() є app_main(), який запускає цей цикл окремою задачею FreeRTOS, але суть та сама.

Як збирається прошивка

  1. PlatformIO бере ваші .cpp і вихідний код ядра Arduino.
  2. Усе це компілює звичайний компілятор C++ (GCC): для ESP32-C3 — riscv32-esp-elf-g++, для STM32 — arm-none-eabi-g++.
  3. Виходить один файл прошивки firmware.bin.

Тобто це повноцінний C++: класи, enum class, constexpr, посилання, шаблони. У прошивці проєкту ми все це використовуємо.

Навіщо Arduino, якщо можна писати напряму?

«Напряму» — це через бібліотеки виробника чипа. Ось як увімкнути один пін у трьох варіантах:

Arduino — однаково на ESP32 і STM32:

pinMode(10, OUTPUT);
digitalWrite(10, HIGH);

ESP-IDF — лише ESP32:

gpio_reset_pin(GPIO_NUM_10);
gpio_set_direction(GPIO_NUM_10, GPIO_MODE_OUTPUT);
gpio_set_level(GPIO_NUM_10, 1);

STM32 HAL — лише STM32, пін PA8:

__HAL_RCC_GPIOA_CLK_ENABLE();
GPIO_InitTypeDef g = {0};
g.Pin  = GPIO_PIN_8;
g.Mode = GPIO_MODE_OUTPUT_PP;
HAL_GPIO_Init(GPIOA, &g);
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_8, GPIO_PIN_SET);

Тому після проєкту в плані навчання є крок: переписати те саме на STM32 HAL або ESP-IDF (див. розділ 07).

А чому в Arduino IDE файли .ino і там не пишуть #include <Arduino.h>?
Arduino IDE перед компіляцією сама додає #include <Arduino.h> у файл .ino і перейменовує його на .cpp. Через це здається, що «Arduino — окрема мова». У PlatformIO ми пишемо звичайні .cpp-файли, тому підключаємо Arduino.h явно, як будь-яку іншу бібліотеку.

Перед уроками: що таке PlatformIO?

Усі уроки збираються командою pio run, а поруч із кодом лежить файл platformio.ini. PlatformIO — це не мова, не компілятор і не фреймворк. Це інструмент, який керує проєктом: сам завантажує потрібний компілятор і бібліотеки, збирає прошивку, прошиває плату і показує лог (Serial Monitor).

Він складається з двох частин:

  • PlatformIO Core — програма командного рядка pio, написана на Python. Саме її запускає ШІ-агент.
  • PlatformIO IDE — розширення VS Code: кнопки ✓ (збірка), → (прошивка), 🔌 (монітор) на нижній панелі. Під капотом вони викликають той самий pio.

Аналогія з UnityЯкщо Arduino — це «рушій» з API, то PlatformIO — це Unity Hub + Package Manager + кнопка Build and Run в одному. Сам по собі він не знає, як мигати світлодіодом; він знає, де взяти все потрібне і як це зібрати.

Хто за що відповідає

Що відбувається при pio run -e l01_blink

  1. PlatformIO читає platformio.ini і бере секцію [env:l01_blink] разом зі спільною [env].
  2. Якщо платформи й компілятора ще немає — завантажує їх. Перший раз це довго, далі все береться з кешу.
  3. Завантажує бібліотеки з lib_deps у .pio/libdeps/<env>/.
  4. Компілює ваш код, ядро Arduino і бібліотеки компілятором GCC (для ESP32-C3 — riscv32-esp-elf-g++).
  5. Лінкує все в .pio/build/<env>/firmware.elf і firmware.bin.
  6. З -t upload — прошиває плату: ESP32 через esptool, STM32 через dfu-util або ST-Link.

Чому в цьому курсі PlatformIO

  • Один проєкт для двох чипів: прошивка збирається для ESP32-C3 і STM32F411 з того самого коду — різниця лише в env.
  • Відтворюваність: платформа і версії бібліотек записані у файлі, тож у вас, в агента і в Wokwi збирається одне й те саме.
  • Замкнений цикл з ШІ: агент сам запускає pio run, читає помилки компілятора і виправляє код (див. розділ 02).
  • Шлях росту: пізніше можна змінити framework = arduino на espidf чи stm32cube і лишитися в тому ж інструменті.

Як встановити PlatformIO і що робити, якщо збірка падає на Windows, — у розділі 03.

Що буде, якщо видалити папку .pio?
Нічого страшного: це лише результати збірки і завантажені бібліотеки. Наступна команда pio run усе відновить, просто збірка триватиме довше. Компілятори при цьому не зникнуть — вони лежать у спільному кеші %USERPROFILE%\.platformio.
Чи можна працювати з PlatformIO без VS Code?
Так. VS Code з розширенням — лише зручні кнопки. Усе те саме робить команда pio у будь-якому терміналі; саме так нею користується ШІ-агент.

Урок 01 — Blink без delay()

Мета: зрозуміти setup()/loop(), millis(), вивід у Serial Monitor. Схема: нічого не потрібно, використовуємо вбудований LED на GPIO8.

У повному файлі уроку перший рядок — #include <Arduino.h> (чому — див. блок вище). Нижче — головна частина коду.

constexpr int PIN_LED = 8;            // вбудований LED (active-low: LOW = світить)
uint32_t lastToggle = 0;
bool ledOn = false;

void setup() {                       // ≈ Start()
  Serial.begin(115200);
  pinMode(PIN_LED, OUTPUT);
}

void loop() {                        // ≈ Update()
  uint32_t now = millis();
  if (now - lastToggle >= 500) {
    lastToggle = now;
    ledOn = !ledOn;
    digitalWrite(PIN_LED, ledOn ? LOW : HIGH);
    Serial.printf("[blink] led=%d\n", ledOn);
  }
}
Чому now - lastToggle >= 500, а не now >= lastToggle + 500?
millis() має тип uint32_t і через ~49.7 доби переповнюється до 0. Різниця беззнакових чисел залишається правильною навіть після переповнення, а сума — ні: таймер «завис» би.

Зміни сам: «серцебиття» — два короткі спалахи, потім пауза 1 с. Підказка: масив тривалостей і індекс кроку.

Урок 02 — Кнопки, pull-up і брязкіт контактів

Схема: кнопка між GPIO4 і GND. Зовнішній резистор не потрібен — pinMode(PIN, INPUT_PULLUP) вмикає внутрішній.

bool raw = digitalRead(PIN_BTN) == LOW;          // натиснута = LOW
if (raw != rawPrev) { rawPrev = raw; changedAt = now; }

  stable = raw;
  if (stable) pressedAt = now;

}
if (stable && !longSent && now - pressedAt >= 700) { longSent = true; Serial.println("[btn] LONG"); }

Урок 03 — ШІМ і MOSFET: керуємо яскравістю стрічки

Схема: ключ на AO3400 — див. розділ 05. Без стрічки можна взяти звичайний світлодіод з резистором 220 Ом на GPIO10.

// Arduino-ESP32 3.x: канал LEDC прив'язується до піна автоматично
ledcAttach(10, 20000, 10);           // пін, частота, роздільність (0..1023)
float level = 0.5f;                      // 50 % «на око»
float out = powf(level, 2.2f);          // гамма-корекція → ~22 % часу
ledcWrite(10, (uint32_t)(out * 1023));
Навіщо гамма-корекція?
Око сприймає яскравість приблизно логарифмічно. Лінійна зміна заповнення виглядає так: стрічка довго «майже на максимумі», а потім різко гасне. pow(x, 2.2) робить зміну рівномірною на око.
Можна спалитиСпільна земля БЖ і плати обов'язкова. Не живіть стрічку від піна 5V плати — USB дає лише ~0.5 А.

Зміни сам: useGamma = false — порівняйте на око. Спробуйте частоту 200 Гц і подивіться на стрічку через камеру телефону: з'являться смуги.

Урок 04 — АЦП і фоторезистор

Мета: перетворити напругу на число, а число — на люкси. Схема: 3V3 → LDR → GPIO0 → 10 кОм → GND (див. дільник).

uint32_t mv = analogReadMilliVolts(0);        // калібровані мілівольти
float v = mv / 1000.0f;
float rLdr = 10000 * (3.3f - v) / v;          // опір з дільника
float lux = 10 * powf(RL10 / rLdr, 1 / GAMMA);  // модель фоторезистора
filtered += 0.2f * (lux - filtered);            // згладжування ≈ Mathf.Lerp
Фоторезистор — не люксметрПараметри RL10 і GAMMA у різних партій відрізняються в рази. Тому аналоговий датчик дає приблизні люкси, і поріг краще підбирати «на місці». Для точних значень є BH1750 (урок 06).

Зміни сам: закрийте датчик пальцем, посвітіть ліхтариком і запишіть значення. Після уроку 06 підберіть RL10/GAMMA так, щоб показники зблизилися з BH1750 — це і є калібрування.

Урок 05 — PIR-датчик руху HC-SR501

  • Живлення 5 В, а вихід — 3.3 В: можна напряму на GPIO3.
  • Tx (час) — на мінімум (~3 с). Скільки світити, вирішує прошивка.
  • Перемичка H — повторний тригер: поки людина рухається, сигнал не падає.
  • Sx — апаратна чутливість (дальність до ~7 м).
  • Після ввімкнення модулю потрібно 30–60 с на «прогрів»: у цей час можливі хибні спрацювання.
Програмна чутливістьУ проєкті є параметр «Фільтр руху»: сигнал має триматися N мс, щоб зарахуватися. Це відсікає короткі хибні імпульси.

Зміни сам: виміряйте мінімальну тривалість HIGH при Tx на мінімумі. Додайте фільтр «HIGH довше N мс».

Wire.begin(6, 7);                                // SDA, SCL

BH1750 bh;  bh.begin();  float lux = bh.readLightLevel();
Сканер нічого не знаходить. Що перевірити?
1) Живлення модуля (3V3 і GND). 2) Чи не переплутані SDA і SCL. 3) Чи збігаються піни у Wire.begin() з реальними дротами. 4) Чи є спільна земля. 5) Контакт у макетці: поворушіть дроти.

Зміни сам: підключіть одночасно BH1750 і OLED — сканер має знайти 0x23 і 0x3C.
